## The migration that had to run first

Production held **1172 garage vehicles, 1041 of them with no `approvalStatus` field at all** — they predate the approval feature. The new code gates on `approvalStatus !== 'approved'`, and `undefined !== 'approved'`, so restarting without a migration would have told 1041 vehicle owners *"this vehicle is awaiting admin approval"* the moment they tried to accept a booking.

Grandfathered them as `approved` before the restart — they were already in use.

| | before | after |
|---|---|---|
| vehicles missing the field | 1041 | **0** |
| approved | 106 | **1147** |
| rejected (left untouched) | 25 | 25 |
| garage drivers missing the field | 0 | 0 |

The 25 an admin had explicitly rejected were not touched.

## Order of operations

1. `git pull --ff-only` — code on disk, old process still serving
2. `npm run build` (backend) — pass
3. `npm run build` (admin) — pass
4. **Migration** — 1041 vehicles grandfathered
5. `pm2 restart admin`, then `pm2 restart backend`

Between steps 3 and 5 `alpha.goracabs.com` threw *"a client-side exception has occurred"*: the admin build had replaced `.next` while the old `next start` process was still serving the previous chunk hashes. The restart fixed it — `/login` is 200 and every chunk the page references resolves 200.
