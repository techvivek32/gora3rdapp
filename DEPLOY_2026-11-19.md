## Order of operations

1. `git pull --ff-only` — code on disk, old processes still serving
2. `npm run build` (backend) — pass
3. `npm run build` (web) — pass, 9 routes, home 12.6 kB / 151 kB (identical to the local build)
4. `pm2 restart backend` → `pm2 restart web`

`admin` was deliberately left alone — nothing in these commits touches it, and restarting
it would have risked the chunk-hash problem seen on 27 Oct for no benefit.

## Android build — `1.3.1+49`

### Version

`1.3.0+48` → **`1.3.1+49`**. Play currently serves **47 (1.3.0)**. The version *code* only
had to beat 47, but 48 was skipped on purpose: local builds carrying code 48 already
existed on this machine, and reusing the number invites confusion over which 48 is which.
The version *name* moved to 1.3.1 because this build is not the 1.3.0 that is live — it
turns on R8, adds Crashlytics and reorders startup. Shipping that under an identical name
makes "which version are you on?" unanswerable for support.

## Before this AAB goes to Play

1. **Data safety declaration.** Crashlytics now collects crash logs and diagnostics.
   Play Console → App content → Data safety has to say so *before* the release, or it is
   a policy violation.
2. **Razorpay checkout is still untested under R8.** Every other native plugin was
   exercised on a release build and passed; this one could not be, because the local
   backend has no Razorpay keys. It is the single most R8-sensitive path in the app — a
   broken payment callback means the user is charged and the app never finds out.
3. **Release in stages, not to everyone.** 5% → watch Crashlytics for a day → 20% → 50%
   → 100%. The crash rate this release is meant to fix is 2.27%, which means roughly 1
   session in 44; a staged rollout is the only way to see whether it actually moved
   before it reaches all 6,700+ users. Until now there was no crash reporting at all, so
   this is the first release where that feedback exists.
