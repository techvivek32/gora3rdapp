## 2. Separate One Way / Round Trip per-km price

Set up on the local DB: **Sedan** given a round-trip rate of ₹60/km (one-way stays
₹100/km). **SRT** was deliberately left with *no* round-trip rate, to prove the
fallback.

Route Ahmedabad → Jaipur, 26 Nov → 29 Nov.

### Round Trip (1310.8 km billed)

| | SRT (no RT rate) | Sedan (RT ₹60) |
|---|---|---|
| Gujarat one-way rate | ₹100/km | ₹100/km |
| Rate actually charged | **₹100** — fell back | **₹60** — round-trip rate |
| Base = km × rate | 131,080 | 78,648 |
| + driver allowance (4 days × ₹350) + 12% GST | **₹1,48,378** | **₹89,654** |
| after discount | ₹1,33,697 | ₹79,965 |

### One Way (655.4 km) — the control

Both cabs quote **₹73,969**, identical, because both are ₹100/km one way.
That is the proof: the two cabs are the same price one way and 40% apart round
trip, which can only come from the new round-trip rate being applied.

A cab with no round-trip rate configured is charged **exactly** what it was
charged before this change. No migration needed.

## 7. Notification sound — root cause and fix

The booking push was not being *lost*, it was arriving **silent**.

- The backend posts booking pushes on channel `gora_cabs_notifications_v4`
  (`notifications.service.ts:16`).
- The app creates that channel with **`playSound: false`**
  (`push_notification_service.dart:28`) — on purpose, so that when the pop-up
  card shows and the app plays the chosen ringtone, you don't hear two sounds.
- So a booking only makes a noise if the app's own code plays it.
- The background isolate returned early — playing nothing — in three cases, and
  Android had already put a silent entry in the tray:
  1. alerts toggle off (intended),
  2. **driver offline**,
  3. **AlertGate refused the alert** because another booking was mid-card.

Cases 2 and 3 are the "sometimes there is no sound".

Checked and ruled out: the bundled tones are not missing — `gora_ring2.mp4` and
`ring-2.mp4` both exist and `assets/audio/` is declared in `pubspec.yaml`.

### What changed

`AlertGate.claim()` collapsed two different questions into one yes/no. Split it:

- `AlertGate.isDuplicate(key)` — the same booking twice. **The only silent case.**
- `AlertGate.takeWindow()` — is the one overlay window free? Only the card needs
  it; the audio player is per-isolate and was never part of the hang the gate
  was written to prevent.

New rule, the same in the foreground and the background:

| State | Tray entry | Sound | Pop-up card |
|---|---|---|---|
| Online, first booking | yes | yes | **yes** |
| Online, 2nd booking while a card is up | yes | **yes** (was silent) | no |
| Offline | yes | **yes** (was silent) | no |
| Same booking arriving twice | yes | no | no |
| Alerts toggle off | yes | no | no |

A fourth silent path was fixed in the foreground too: if a loud alert arrived
with no navigator yet (startup, or between routes), no card could be shown, yet
the notification was still built on the silent booking channel. It now always
uses the audible updates channel, because reaching that code means no card is
coming.

Tests: `mobile/test/alert_gate_test.dart`, 7/7. `flutter test` 11/11 overall,
`flutter analyze` 0 errors.

**Not yet confirmed with a real push on a device** — that needs a fresh build
and two bookings fired back to back.
